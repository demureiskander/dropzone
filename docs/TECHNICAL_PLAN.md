# Технический план

Дата: 2026-09-08. Ниже предложенная архитектура и план проверки, а не реализованные компоненты.

## Выбор основы

Предлагаю нативное приложение на Swift: AppKit для полки, управления фокусом и drag-and-drop; SwiftUI для настроек и содержимого окна. Предварительная базовая платформа — macOS 13, с последующей проверкой доступности используемых API и сборок arm64/x86_64. Использовать Xcode-проект приложения; модель можно выделить в локальный Swift Package для тестирования.

Причина выбора — тесная работа с системными окнами и межприложенным drag-and-drop. Apple документирует file URLs, file promises и отдельные window collection behaviors для Spaces, full-screen и Stage Manager. Эти API дают основу; корректность сочетания флагов и поведение поверх чужих полноэкранных окон нужно подтвердить на практике. [AppKit drag-and-drop](https://developer.apple.com/documentation/appkit/supporting-collection-view-drag-and-drop-through-file-promises), [Window collection behaviors](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct?changes=_7%2C_7).

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| AppController | Menu bar, запуск, настройки, жизненный цикл процесса |
| ShelfStore | Элементы, выделение, видимость, стабильные идентификаторы |
| ShelfWindowController | NSPanel, позиция, уровень, фокус, экран, Spaces |
| ActivationController | Shake, shortcut, исключение повторных срабатываний |
| NotchDropController | Геометрия выреза, зона приближения/приёма, подсветка, обновление при смене дисплеев |
| FollowController | Сглаживание скорости, выбор стороны, пауза при взаимодействии, сохранение режима |
| DragImportService | Разбор pasteboard, file URLs; позже file promises и текст |
| DragExportService | Системная dragging session, выбранные элементы, copy-only P0 |
| PreviewService | Асинхронные миниатюры, ограниченный cache, Quick Look |
| SettingsStore | Сохраняемые предпочтения и их версии |
| TemporaryContentStore (P1) | Только созданные приложением копии, retention и безопасная очистка |

## Сложные места, которые проверяем первыми

**Распознавание жеста.** Глобальное движение мыши при зажатой кнопке не всегда является переносом файла: это может быть выделение текста или движение окна. Прототип должен отличать допустимый drag настолько, насколько позволяет macOS, не перехватывать ввод и не запускать полку на обычном движении. Начать с ограниченного буфера траектории, смен направления и временного окна; пороги настроить по реальным записям мыши/трекпада. Accessibility/Input Monitoring могут потребоваться в зависимости от API: подтвердить точный запрос экспериментом, не добавлять оба разрешения автоматически.

**Окно без захвата фокуса.** Проверить NSPanel и режим без автоматической активации при drag, отдельно — явный клавиатурный вход. Подобрать допустимые collection behaviors под minimum OS. Проверить full-screen чужого приложения, Stage Manager и Open/Save dialogs, а не только несколько окон Finder. [Apple: fullScreenAuxiliary](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary).

**Сохранность файлов.** Модель P0 хранит ссылки на оригиналы и экспортирует копии. Удаление элемента полки не вызывает удаление оригинала. Сам сигнал конца dragging session не является доказательством, что стороннее приложение сохранило файл. Для будущего move нужны отдельные проверки same-volume/cross-volume, отказа назначения и частичного успеха; не реализовывать его как безусловную очистку источника.

**Асинхронный контент.** Для P1 Apple предоставляет NSFilePromiseReceiver/Provider: источник может создать файл только после drop. Нужны очередь фоновой работы, индикатор, ошибка и каталог для принадлежащих нам копий. Один promise может представлять несколько файлов. Когда источник даёт promise и URL как альтернативные представления, не создавать дубликаты. [NSFilePromiseReceiver](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver?language=_9), [пример Apple](https://developer.apple.com/documentation/appkit/supporting-drag-and-drop-through-file-promises?changes=_8).

**Время жизни и доступ.** В P0 сессия живёт до выхода из приложения. Для P1 выбрать и проверить механизм восстановления ссылок/доступа, включая sandbox и bookmarks, внешние изменения и недоступные тома. Временные файлы нельзя удалять, пока они нужны активному экспорту или clipboard. Очистка касается только собственного каталога, никогда исходных файлов пользователя.

## Порядок работ

1. Создать минимальное menu bar приложение и одну NSPanel. Принять file URLs из Finder и выгрузить копии обратно. Проверить отмену и сохранность оригиналов до дизайна.
2. Добавить shortcut, shake и notch с двумя уровнями подсветки. Проверить разрешения, отсутствие ложных срабатываний, расположение и фокус. Вручную прогнать несколько экранов и full-screen.
3. По DESIGN.md собрать компактный вид, раскрытые сетку/список, меню, выделение, превью и настройки. Проверить возможность увеличения drag image входящего файла через публичный API.
4. Реализовать FollowController отдельно от окна и протестировать траектории: разворот, остановка, приближение к полке, пауза для меню/drag-out, границы экрана. Подключить сохраняемый переключатель (default on), проверить достижимость кнопок и drop-цели вручную.
5. Выполнить критерии P0 из MVP.md и DESIGN.md, записать окружение и результаты. Добавить настоящие команды сборки/тестирования в README и CLAUDE.md.
6. Подготовить первую alpha-сборку. До публичного релиза оформить лицензию, отличимое имя, инструкцию установки и процесс подписи/нотаризации; проверить актуальные требования Apple на этапе распространения.
7. Развивать P1 по реальному использованию: сначала источники drag и системный Share, затем несколько полок и автоматизация.
