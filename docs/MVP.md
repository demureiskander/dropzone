# Dropzone MVP

Статус: предлагаемая спецификация от 2026-09-08 на основе [исследования](RESEARCH.md). Функции ниже ещё не реализованы.

## Результат для пользователя

Пользователь берёт несколько файлов из Finder, вызывает небольшую полку рядом с курсором, кладёт туда файлы, добавляет другие из второй папки, переключается в окно назначения и забирает всё или выбранные элементы. Полка готова принимать файлы сразу после появления.

## P0 — первая рабочая версия

| Функция | Граница реализации |
| --- | --- |
| Приложение в menu bar | Меню: показать/скрыть полку, очистить, настройки, завершить; закрытие полки не завершает приложение |
| Одна полка | Перемещаемое окно поверх обычных окон; компактный и раскрытый виды |
| Три способа вызова | Shake при drag, настраиваемая глобальная клавиша, меню; drop на значок menu bar |
| Файлы и папки | Приём file URLs из Finder, несколько файлов, добавление из разных мест |
| Просмотр и выбор | Системные значки/миниатюры, счётчик, имена, множественный выбор, Quick Look, Reveal in Finder |
| Drag-out | Перетаскивание всего набора или выделенных файлов в Finder и совместимые приложения |
| Управление содержимым | Убрать выбранное/очистить полку, без удаления оригиналов |
| Управление видимостью | Скрытие сохраняет содержимое в текущей сессии; вызов возвращает ту же полку |
| Настройки | Активация, чувствительность shake, горячая клавиша, автозапуск, поведение после drag-out, тема |
| Качество | Без захвата фокуса при появлении во время drag, проверка нескольких экранов/Spaces/full-screen, доступность с клавиатуры |

Это намеренно одна полка в v0.1. Несколько независимых полок не нужны для основного сценария накопления и требуют дополнительных правил навигации и восстановления.

## Точная семантика

- Вход обычного файла добавляет ссылку; оригинал остаётся на месте. Повторное добавление того же объекта внутри полки не создаёт дубликат; разные файлы с одинаковыми именами остаются отдельными элементами.
- Предлагаемый default drag-out — копирование. В интерфейсе понятно, какая операция выполняется. Finder-подобное перемещение можно добавить позже после проверки обработки ошибок; не эмулировать move удалением оригинала по одному событию завершения drag.
- По умолчанию после принятого drag-out полка скрывается, сохраняя ссылки для повторного использования. Настройка «Оставлять открытой» сохраняет её видимой. В v0.1 нет автоматического удаления элементов после передачи.
- Отмена или отказ получателя оставляет полку и содержимое доступными. Частичная ошибка не удаляет непереданные элементы. Успех в стороннем приложении определяется доступными сигналами системы; не обещать проверку фактического сохранения там, где API её не даёт.
- Кнопка закрытия скрывает полку; «Очистить полку» удаляет ссылки. Завершение приложения заканчивает временную сессию; восстановление после перезапуска — P1.
- Недоступный оригинал помечается явно. У пользователя остаётся возможность убрать запись. Полка не является копией или резервным хранилищем.
- Полка появляется с небольшим смещением от курсора в пределах доступной области нужного экрана; не перекрывает точку захвата и не прыгает на другой монитор.
- Системные локальные shortcuts работают только в активной полке. Явный клавиатурный вызов может активировать её для управления; жест во время drag не меняет активное приложение.
- Ошибки показываются рядом с затронутым элементом понятным текстом, не исчезают молча.

Копирование по умолчанию и сохранение ссылок после drag-out — предложения для Dropzone, не описание default Dropover.

## Минимальные настройки и defaults

| Параметр | Предлагаемое исходное значение |
| --- | --- |
| Запуск при входе | Выключен, явное включение пользователем |
| Shake для вызова | Включён, если доступно необходимое разрешение; можно отключить |
| Чувствительность | Средняя; низкая / средняя / высокая, интерактивная проба |
| Глобальный вызов | Настраиваемый; конкретное сочетание выбрать при реализации с проверкой конфликта |
| После успешного drag-out | Скрывать полку, сохраняя содержимое |
| Оставлять открытой | Выключено |
| Тема | Системная; светлая / тёмная |
| Положение | Возле курсора, с возможностью вручную переместить окно |

Поддерживать системные Reduce Motion/Reduce Transparency. Первое знакомство — короткий пример «взял → вызвал → положил → забрал» и доступ к способу вызова без жеста.

## P1 — следующий этап

- File promises: картинки из Safari/Photos, вложения и системная миниатюра скриншота; показывать прогресс и управлять временными копиями. Поддержка конкретных источников подтверждается вручную.
- URL и текст, изображения из clipboard по явной команде; без фонового clipboard manager.
- Системное Share/AirDrop.
- Несколько полок, имена, цвета, show/hide all, закрепление и восстановление сессии.
- Пристыковка к краю экрана; Notch как дополнительный способ вызова.
- Исключения приложений для shake, дополнительный вызов модификатором во время drag.
- Перемещение оригиналов с проверенными правилами сохранности и восстановления после ошибок.
- Русская и английская локализация до широкого публичного релиза; строки изначально готовы к локализации.

В v0.1 поддержка обычного файла изображения не означает поддержку изображения, которое браузер ещё должен экспортировать. При неподдерживаемом типе нужен понятный отказ. Если ручной сценарий со скриншотами окажется обязательным по уточнениям автора, file promises нужно перенести в P0.

## P2 — после проверки спроса

Мониторинг папок и скриншотов, Shortcuts/Services/Share Extension, Raycast/Alfred, CLI, ZIP, преобразования, OCR, настраиваемые действия, скрипты, облачные интеграции. Собственное облако требует отдельного решения о содержании сервиса.

## Критерии готовности v0.1

1. Два набора из разных папок собираются в одной полке; выбранные элементы и весь набор можно передать раздельно.
2. Finder получает копии; оригиналы остаются неизменными. Проверить разные тома, дубликаты имён, Unicode и папки.
3. Escape/отмена drag, отказ получателя и недоступный destination не приводят к потере содержимого или исходных файлов.
4. Внешнее переименование/удаление оригинала обрабатывается без crash; недоступность отображается понятно.
5. Обычный drag без shake не открывает полку; отключённый shake не срабатывает; настраиваемый shortcut работает при активном Finder.
6. Скрытие/повторный вызов сохраняет содержимое; очистка не отправляет оригиналы в Trash; закрытие последней полки не завершает приложение.
7. Проверены мышь и трекпад, два экрана, разные масштабы, Spaces, full-screen приложение, sleep/wake и отключение внешнего дисплея.
8. Появление во время drag не перехватывает фокус; клавиатура и Quick Look работают после явной активации.
9. Пакет из 100 обычных файлов и ссылка на большой файл не блокируют интерфейс; прототип измеряется на записанной модели Mac и версии macOS.
10. Ориентир появления: p95 ≤150 мс после распознанного триггера на тестовой машине; отдельно измерять распознавание жеста. Это целевой бюджет, не заявленный результат.
11. В idle нет постоянной анимации или активного опроса с высокой частотой; записать CPU/память после 5 минут покоя и повторных циклов drag.
12. Базовая полка из меню работает при отказе в разрешениях для глобального жеста. Нет сетевой зависимости и искусственного ожидания.

UI-референсы определят размеры, материалы, композицию, акценты и характер анимации. До этого можно проверить drag-and-drop и жизненный цикл окна на техническом прототипе.
