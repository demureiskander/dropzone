# Dropzone — контекст и правила разработки

## Цель

Создать бесплатную open source утилиту для macOS с временной полкой для перетаскиваемых файлов. Автору нравится удобство и эстетика Dropover; наша реализация и визуальная идентичность должны быть самостоятельными. Искусственные ожидания, trial, Pro-блокировки и обязательный аккаунт не входят в продукт.

## Текущее состояние

На 2026-09-08 реализована первая нативная alpha: file URLs, compact/grid/list, notch/shake, системный shortcut, Quick Look, настройки и инерционное следование. Сборка и 22 теста прошли на macOS 26.5.2 arm64. Полную матрицу ручной проверки см. в docs/VALIDATION.md. Не выдавать непроверенные сценарии за подтверждённые.

Перед реализацией прочитать:

- `docs/RESEARCH.md` — факты и источники, с датами и оговорками об исторических отзывах.
- `docs/MVP.md` — границы MVP и критерии приёмки.
- `docs/DESIGN.md` — актуальные UI-референсы, notch и следование за курсором.
- `docs/TECHNICAL_PLAN.md` — порядок проверки технических рисков.

Рабочее имя — Dropzone. Совпадение с продуктом Aptonic зафиксировано в README; не переименовывать проект самостоятельно.

## Принципы продукта

- Главная функция — положить содержимое, переключить контекст, забрать его.
- Интерфейс компактный, нативный, с ясными состояниями и короткими анимациями; визуальные решения уточнять по референсам.
- Shake отключаемый; доступны клавиатурный вызов и меню.
- Notch входит в MVP: ореол при приближении и обводка в активной drop-зоне.
- Follow-режим входит в MVP и включён по умолчанию; кнопка на полке сохраняет выбор между запусками. Фиксировать окно при приближении пользователя и во время взаимодействия, чтобы оно не убегало.
- Появление полки во время drag не забирает фокус у исходного приложения.
- Приём обычного файла хранит ссылку на оригинал. Очистка полки не удаляет оригинал.
- Отмена, неуспешный drop и частичный сбой не должны приводить к потере файлов или исчезновению непереданных элементов.
- MVP работает локально, без аналитики, сетевых сервисов и фонового чтения истории буфера обмена.
- Облака, конвертации, скрипты и clipboard manager не добавлять в MVP без изменения его согласованного объёма.

## Реализация

Основа — Swift + AppKit + SwiftUI. Swift Package содержит DropzoneCore и executable Dropzone. scripts/build.sh упаковывает executable в обычный .app. Package.swift открывается в Xcode; отдельный сгенерированный xcodeproj не требуется.

Разделять модель полки, импорт/экспорт, хранение временных данных, активацию, управление окнами и представление. Работа с файлами и превью не должна блокировать UI. Не считать drag завершённым успешно только потому, что отпущена кнопка мыши.

Не использовать имя файла как уникальный идентификатор. Не читать многогигабайтные обычные файлы целиком ради помещения на полку. У временных копий и ссылок на пользовательские оригиналы должен быть разный жизненный цикл.

Разрешения macOS запрашивать только для реализованной возможности, объясняя её назначение. Точный набор разрешений определяется проверкой прототипа; не обещать отсутствие запросов заранее. Базовая полка через меню должна оставаться доступной, если пользователь отказал в разрешении для жеста.

Использовать публичную документацию как источник поведения, писать собственный код и создавать свои графические материалы. При добавлении стороннего кода фиксировать происхождение и лицензию.

## Проверка изменений

Запускать `swift test`, `scripts/build.sh release`, `codesign --verify --deep --strict build/Dropzone.app` и `git diff --check`. В ограниченной среде компилятору может потребоваться разрешение на его служебные кэши и sandbox.

Проверять значимые состояния, особенно отмену drag, частичные ошибки, одинаковые имена файлов, временные данные, пропавшие оригиналы, несколько экранов и фокус. Нативное межприложенное перетаскивание проверять вручную в дополнение к тестам модели. Не объявлять поддержку платформы или сценария без проверки.

## История и документация

- Обновлять `CHANGELOG.md` при каждом значимом изменении поведения или структуры проекта.
- Поддерживать актуальность README и спецификации при изменении объёма.
- Делать небольшие осмысленные коммиты; не переписывать и не удалять чужие изменения.
- Не включать в Git сборки, пользовательские файлы, ключи подписи и секреты.
- Не выдумывать команды сборки, результаты тестов, замеры производительности и ссылки на релизы.

Работать на GitHub строго с `demureiskander/dropzone` (https://github.com/demureiskander/dropzone.git), как указал пользователь. Другие репозитории не читать и не изменять. Лицензия — Apache-2.0; иконка создана для проекта, происхождение и промпт в Resources/ASSET_PROVENANCE.md.

Закрытие крестиком/⌘W очищает ссылки с настраиваемым подтверждением (>5 по умолчанию); Esc только скрывает. ⌘, открывает настройки по физической клавише в фокусе приложения. Follow настроен на быстрый отклик без лимита скорости. Используется финальная иконка, присланная автором.

Открытые решения: настройка анимации по обратной связи, итоговое публичное название, подтверждённый минимум macOS, Developer ID подпись и распространение релиза. Они не препятствуют локальному техническому прототипу.

Язык приложения: English по умолчанию, русский в General → Language, хранится отдельно от языка системы. Все новые строки добавлять в Localization.swift и вызывать через L. Зона остановки follow — 20 pt, возобновления — 44 pt.

Показ/скрытие полки используют прерываемый fade 180/140 мс; Reduce Motion — 80 мс. Низкая чувствительность shake 0.35, сохранённое 0.7 мигрирует.

Релизы: первый публичный alpha v0.1.0 опубликован, assets DMG/ZIP/SHA256SUMS (arm64). Homebrew tap размещён в этом же репозитории; cask `demureiskander-dropzone`, установка проверена. `scripts/package.sh` собирает assets; версия/хэш cask должны совпадать с опубликованным DMG. LICENSE/NOTICE включены в .app. Новая присланная автором иконка заменяет предыдущие варианты.

По умолчанию значки Dock и строки меню включены. Независимые настройки showDock/showMenuBar сохраняются, применяются сразу. Если оба выключены, повторное открытие приложения показывает настройки.
